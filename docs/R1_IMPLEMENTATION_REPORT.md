# R1 — Production stability and AI quality baseline

Implemented against `main` at `1ac623d`. No database migration, live database operation, deployment, provider/model change, or new infrastructure.

## Completed

- Normal production (including Render) requires credentialed Admin Firestore. Explicit persistence bypass is rejected. Hydration failure prevents HTTP listening. Production startup does not merge local JSON into remote authoritative state.
- Production requires a stable random session secret of at least 32 bytes, without known placeholder patterns. Demo authentication cannot be enabled there. HTTPS cookie and Render proxy handling remain compatible.
- Demo users/quizzes are seeded only for tests or explicit development demo mode. Existing remote users, ownership and quizzes are preserved. Hydration no longer discards a legitimate remote quiz merely because its ID matches a sample ID.
- Public health reports ready, degraded or unavailable without configuration, paths, errors, counts or credentials. Detailed persistence and pending/failed-write counts remain behind administrator authentication.
- Per-document ordered writes now deduplicate at execution, fixing A → B → A. Progressive payloads are immutable snapshots. Awaited progress checkpoints coalesce for up to three seconds; the save endpoint acknowledges durability only after completion. Individual academic grades may precede their background checkpoint. A crash can lose unacknowledged progress; browser local recovery remains available.
- Final submissions require acknowledged persistence, retain idempotency/revision/digest protections, and remain unfinalized after failed persistence. Newly generated AI/worksheet quizzes enter production hot state only after acknowledgment. Invalid persistence targets reject. Failed writes cause shutdown flush failure until the affected target succeeds.
- Graceful shutdown drains HTTP before flushing writes, including delayed checkpoints. Fatal process errors initiate shutdown. Chunk metadata is published only after all chunks complete; tests inject failure before publication and rehydrate the previous generation.
- Modern results use exact persisted user identity, quiz ownership/admin or a result token. Name/email-like display text no longer grants access, including quiz result listings. Legacy high-entropy 20-character final result links remain supported.
- Registered attempt mutations/restoration reject other identities. New anonymous production attempts require the cryptographic session IDs already generated by the client. Public quiz taking still requires no registration. Live scores use server result totals, finalized attempts retain completed status, inactive sessions expire after two hours, and production Socket.IO HTTP/WebSocket origins are restricted.
- Worksheet preflight checks all uploads before AI/raster work: magic bytes, readable PDFs, total pages, dimensions, pixels, animated image rejection and cumulative RGBA work. Two upload requests and two raster canvases run at once; the canvas cap is six million pixels. Failure paths release buffers/PDF resources.
- Every hosted call receives an execution deadline and request cancellation signal. Hung operations that ignore abort are bounded at the wrapper. Model queues honor upstream numeric/date Retry-After and cooldowns, bound queue size, and preserve ordering during cancellation. Permanent solver failures and cancellation do not get validation retries. Identical active authoring jobs are rejected; leases release idempotently.
- Provider/parser diagnostics omit raw output and error objects in touched AI paths. Stored BYOK keys remain supported but are removed from administrator exports/list responses. No risky credential-format migration.
- CI runs clean install, TypeScript/regression suite, build, mocked evaluation and dependency classification on PRs/main. Existing suite validates EJS/JS/CSS as well as grading/worksheet contracts. New unknown advisories and critical advisories fail classification; reviewed retained advisories are explicitly documented.

## Unchanged behavior / remaining limits

- Existing collections, chunk format, source numbering, independent verification, golden-key handling, grading proofs and teacher edit invalidation remain in place.
- Attempt locks, RPM buckets, job state and live classroom controls remain process-local. No Redis or multi-process support was added.
- Checkpoints cannot preserve work that was never acknowledged before abrupt termination. Local snapshots are recovery aids, not production authority. Retained failed-target diagnostics do not autonomously replay a caller's rolled-back critical mutation.
- Multi-document deletion/transfer and dual-database writes are not atomic transactions. An ambiguous remote acknowledgment can require operational reconciliation; no destructive repair is automatic.
- Native PDF parsing and retained extracted-image/base64 material are not a hard OS memory sandbox. Limits bound accepted work and canvases; production RSS under realistic simultaneous workloads remains unmeasured.
- API keys remain in existing server-side user storage. Export/log exposure fixes do not provide at-rest encryption.
- Live classroom room membership remains the existing public-quiz protocol; origin restriction and score authority do not constitute full teacher/student room separation. A future security phase should separate teacher telemetry rooms.
- Actual visual/model accuracy, provider quota behavior, deployment readiness and production restart/shutdown drills remain unverified.
