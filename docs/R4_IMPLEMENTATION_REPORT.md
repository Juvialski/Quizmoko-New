# R4 — Simplified teacher workflows and application UI

Implemented in the existing EJS application from main `045765a` on one implementation branch. No production Firestore operations, migration, reset, live Gemini calls, personal Chrome profile access, desktop interaction, manual deployment or R5 work occurred.

## Implemented screens

- **Dashboard/library:** four compact actions, recent quizzes, draft/published summaries, title search and subject/folder/status filters over existing hydrated data. Cards show publication status, question/review counts and Edit, Preview, Share and Results. Duplicate/move/export/delete/live tools remain secondary; dropdown parent stacking remains intact. Modification ordering prefers existing/new update timestamps. No additional Firestore reads or replacement library.
- **AI generator:** the existing form now presents five essential fields: topic, subject, question count, question type and difficulty. Defaults are ten multiple-choice questions, balanced difficulty, zero diagrams and existing timing/batch/model defaults. Advanced Options retains the original distribution, model, diagram, style, mode, timing and batch controls. BYOK and configured Ollama remain accessible. Mixed counts must equal the requested count, difficulty must total 100, and diagrams cannot exceed questions. Submission is locked before asynchronous key selection; JSON requests use the existing API, preserve inputs on failure and explain Retry-After. The server does not expose per-stage generation telemetry, so the UI honestly says questions are being generated and answers checked, without invented percentages or verification claims.
- **Editor:** title and draft/published/save state, Preview, Save Draft/Changes, Publish and published-only Share lead the page. Quiz and question tools use native disclosures. One selected question is expanded, with original worksheet labels, a compact jump navigator, Needs review filter and remaining count. Manual Add Question works without AI. Choices, answer and optional explanation are editable; advanced grading and evidence remain secondary. Concise labels summarize verification without changing authoritative rules. Bulk approval/deletion still require their existing explicit actions.
- **Save/publish/preview:** existing update endpoints receive optional save intent and expected revision/content version. Ordered per-quiz updates wait for existing persistence acknowledgment and rollback. New UI drafts remain private until explicit publication; publication validates the complete canonical set and rejects review blockers. Intent-less legacy callers retain their behavior. Existing published records are untouched. Blank quizzes start private, and generator/worksheet UI opts into draft creation. Unsaved navigation warns; no-change saves avoid requests; failed/conflicting saves retain edits; edits made while a save is running remain dirty. A stale two-tab save returns 409 rather than overwriting newer data.
- **Teacher preview:** new owner/admin-only `/preview/:quiz_id` displays saved sanitized student content and original labels, without attempt/session/grading/submission scripts or record creation. Stored HTML is escaped at the EJS boundary and rebuilt through a closed inert formatting/image subset in `teacher-preview.js`; source scripts, event handlers and unsafe URLs cannot run. Unsaved edits must be saved to appear there. It is a read-only question appearance preview, not a simulated student attempt/timer/whiteboard.
- **Worksheets:** an explicit Upload → Review extraction → Check answers → Create draft → Review and publish sequence, supported formats/default limits, removable selected files, secondary extraction settings and clearer draft actions. Existing source text/images/crops, recovery, exact printed identifiers, golden keys and approvals remain. Answer-key review labels distinguish verified, teacher-supplied, conflicting and unverified answers. Ordinary worksheet solving still proceeds to the existing editor for full answer review; no second solver or persistence path was added. RMX Flash and answer-key paths remain available.
- **Results/feedback:** compact student search, clearer View feedback actions, readable existing score/completion tables, secondary assessment tools and retained correction/export/audit paths. Browser testing found and fixed a pre-existing `qMisses` scope error that prevented nonempty result pages from rendering. No historical regrading occurred.
- **Shared design/accessibility:** consistent inputs, 44px minimum controls, focus indicators, denser cards, native keyboard disclosures, labeled legacy/dynamic controls, modal focus trap/return and responsive question/diagram containers. Existing light/dark themes and math rendering remain.

The browser script renders the pinned main dashboard for comparison, using synthetic records. Measurements are actions/control counts, not speed or human study results.

| Measure | Main before R4 | Implemented R4 |

| Start default basic generation | Not measured as a comparable click benchmark | Open generator, enter topic, press Generate: 3 actions; one outgoing request under repeated-click test |

No timing or classroom performance improvement is claimed. Folder grouping still orders each group and the groups by most recent timestamp, rather than replacing folders with a global list. Verification labels are presentation summaries; they do not certify unsupported mathematics or diagram semantics.

## Remaining limits

Live Firebase sign-in, real provider generation/extraction, actual handwritten worksheet fidelity, advanced crop/Kroki rendering and production acceptance were not exercised. Synthetic worksheet bytes are intentionally intercepted by the mock extraction boundary; real upload decoding/security remains covered by existing regression tests. The answer-key and RMX specialized flows retain their existing engines; answer-key upload layout is tested, while its full specialized creation journey and RMX/browser export are deferred. Results retain a horizontally scrollable table inside the mobile page. There is no full screen-reader audit, human usability timing study, automatic conflict merge or durable cross-process edit coordinator.

Draft saves continue to require structurally valid canonical questions; incomplete answers can remain review-required, but invalid structural records are rejected by the existing validator. Legacy API callers intentionally retain legacy publication behavior. Existing batch-approval/edit semantics are preserved rather than redefined in this UI phase. Generation has no new server-stage event stream. Optional CDN availability is distinct from hermetic CI and advanced visual acceptance.

The next recommended work is a teacher-led acceptance session with representative worksheets, keyboard/screen-reader review and bounded credentialed provider/diagram checks, followed by prioritizing those findings. No R5 implementation has begun.
