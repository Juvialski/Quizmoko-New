## Confirmed findings

### F1 — P0: opening an unchanged published quiz can manufacture review failures

**Reproduction (production, twice):** open an existing worksheet-derived published quiz with diagrams; initially observe Published/Saved and zero review items. Leave later question images offscreen for more than ten seconds. The editor becomes Draft/Unsaved changes and reports diagram rendering failures for four questions. Scroll through them: the embedded images decode successfully. The five source images ultimately measured 183×159, 199×122, 221×192, 356×297 and 547×731. No content fields were edited and nothing was saved.

**Evidence:** local `production-editor-auto-dirty.png`, `production-editor-question25.png`; repeated reload snapshot; network capture contained no corresponding failed image request. The only recorded HTTP failure was unrelated usage statistics (403).

**Root cause:** `views/edit_quiz.ejs` sanitization adds `loading="lazy"`. `updatePreview()` starts a ten-second timer immediately for every guarded image, including offscreen lazy images. `!image.complete` calls `markQuestionNeedsReview()` even when the browser has not started loading it. That function clears approval, marks the question dirty and refreshes publication/review UI. Successful later image loading clears the timer but does not undo the earlier mutation. Review count makes `refreshPublicationControls()` display Draft even if the stored quiz remains published. This is a local-state defect; production unpublication was not executed or demonstrated.

**Smallest proposed correction (review first):** distinguish not-yet-requested lazy images from completed decoding failures; start bounded failure detection when loading is actually attempted. Scope callbacks to the current image/render generation and make reporting idempotent. Transient preview state must not silently rewrite academic approval. Preserve genuine broken-image and unsafe-diagram publication gates; do not auto-verify after a successful image load. Regression: unchanged long quiz stays clean while offscreen, scroll/decode succeeds, genuine corrupt image still requires review, obsolete callbacks cannot mutate a replacement render. **Complexity: Medium. Not implemented because verification/publication semantics need review.**

### F2 — P1: fabricated provider quota

**Reproduction (production):** open Generate with AI → Advanced Options. Badge reports “1000 / 1000 Requests Left”. The ordinary teacher's usage request returns 403; the server endpoint is admin-only and returns an empty `daily_stats` object even for an administrator.

**Root cause:** three templates sum hardcoded per-key daily allowances and subtract empty usage. This is neither provider accounting nor the actual process-local rolling RPM guard. Missing data becomes an apparently full allowance.

**Implemented correction:** dashboard, worksheet and worksheet + key badges say **Quota unavailable**, or **Local model** for a supported local selection. Initial markup also stays truthful on 403/network failure. Provider/key selection, limiter and hosted model settings are unchanged. Tested without keys, with two synthetic keys, a denied usage endpoint, and both hosted model selections. **Complexity: Small.**

**Remaining related limitation:** the expanded usage dashboard and Sync History still consume placeholder endpoints. Replace those with an explicit unavailable state or remove the unsupported display/action; do not build provider accounting merely to populate a counter. This audit does not claim those placeholders were repaired.

### F3 — P1: RMX Flash mobile header overflows with administrator controls

**Reproduction (local, admin fixture):** open `/rmxflash` at 390px. Header actions extend beyond the viewport (initial full-page capture was 502px wide), separating the controls from the content. Desktop fits.

**Root cause:** the header and its actions have nonwrapping inline flex layout. **Implemented correction:** wrap these two containers below 600px; no extraction behavior changes. Browser regression asserts no document overflow with the Admin Panel action present. Production teacher RMX was inspected, but this admin-only responsive condition was established locally. **Complexity: Small.**
